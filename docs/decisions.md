# Architecture decisions and limitations

1. **Open-Meteo ERA5 archive, not current forecasts.** Use ERA5 for a consistent historical model. Its daily data generally has a processing lag; the default end date is seven days before the run date. This project analyzes *past* weather, not upcoming shipping conditions.
2. **Immutable raw JSON.** Each run writes its API responses (or clearly labeled synthetic demo responses) under `data/raw/<run-id>/`. Raw files are not added to Git.
3. **Three data layers.** Bronze = typed source fields, Silver = cleaned dates and explainable risk features, Gold = city/month aggregates. Parquet outputs under `lake/silver/latest` and `lake/gold/latest` are **run-window snapshots**, not incremental history tables.
4. **Idempotent SQL sink.** `weather_daily` has primary key `(city, record_date)` and performs `INSERT .. ON CONFLICT DO UPDATE`. Different backfill windows can be run repeatedly without double-counting. If a reanalysis value changes, the latest successful ingest replaces that date.
5. **SQLite local default, PostgreSQL optional.** SQLite removes infrastructure friction. PostgreSQL is available with Docker Compose and the `postgres` extra. The connector intentionally streams a bounded number of rows from the Spark driver, suitable for four cities and limited history, not a distributed big-data sink.
6. **Data validation fails closed.** Incomplete API dates, missing fields, impossible temperatures, negative wind/rain, NaN values, and duplicate `(city, date)` are rejected before database writes.
7. **Illustrative risk flags, not business predictions.** Heavy precipitation >= 10 mm/day: +2 points. Max 10-m wind >= 50 km/h: +2 points. Minimum temperature <= 0 C: +1 point. Score 0 = low, 1-2 = medium, 3+ = high. These are teaching heuristics and have **not** been validated against any actual operational disruptions.
8. **Refresh boundaries.** Parquet `latest` folders are overwritten on each run; if a write fails, a snapshot may be incomplete. For production use, stage to a temp path and commit atomically (e.g., Delta Lake), manage transactions across outputs, replace the driver-side SQL sink with Spark JDBC, and add monitoring/orchestration.
9. **No secret credentials.** Public Open-Meteo requests need no API key. `.env` is ignored. Local Docker Postgres credentials are development-only.
10. **Data attribution.** Historical weather is model-based reanalysis, not measurements from an exact local weather station. Real API data carries Open-Meteo attribution and CC BY 4.0 licensing, subject to the service's free-tier/non-commercial conditions.
